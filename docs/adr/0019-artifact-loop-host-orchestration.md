# Artifact loop and host-owned orchestration

Status: accepted

Supersedes the orchestration and recovery decisions in ADR 0018. It keeps
Index compaction, Markdown planning, stable page IDs and late path binding.
There is no compatibility or migration path for prior Run state.

## Context

ADR 0018 separated knowledge planning from page composition, but implemented
the lifecycle as a kernel-owned Target DAG. The host agent had to carry Run
sessions, random Attempt tokens, packet paths, checkpoints, recursive dossier
Targets, two page graphs and per-page review Targets. Those mechanisms
duplicated host subagent orchestration and made recovery harder to operate.

The kernel could compare session strings but could not prove independent
reviewer context. Attempt-specific checkpoints duplicated the long-form
Artifacts they summarized. Publication derived its pages from physical paths,
so a separate parent graph provided no deterministic guarantee.

## Decision

The host follows one explicit loop until Publication or a real external block:

    status -> plan/write/review/repair -> status -> ... -> publish

State stores captured revisions, catalogs, lifecycle status and exact approval
digests. Status derives the phase from fixed files:

    work/plan.md
    work/progress.md
    work/evidence/
    work/composition.md
    work/drafts/<page-id>.md
    work/review.json

One long-lived planner owns cross-Source understanding. Focused subagents may
write evidence notes, but do not create Source Plan shards. Composition assigns
every Knowledge Unit exactly once and is the first place to choose stable Page
IDs and final paths. It carries no owner/scopes copies, parent graph or writer
dependency graph; pages inherit scopes from assigned units and paths encode the
published hierarchy.

The kernel exposes bounded evidence navigation without Target identity. It
validates fixed Artifacts, builds a Candidate, and binds one strict final Wiki
review to the digest of Plan, Composition, drafts and Candidate. A fresh host
subagent provides review independence. Requested changes return to the loop
without a round limit, and every follow-up packet points to the fixed prior
review Artifact. Approval stamps every page, then deterministic Publication
installs an immutable generation. When no knowledge passes the Grep Test, an
explained empty Plan and Composition follow the same review and Publication
path without manufacturing a placeholder page.

Run IDs remain internal storage keys generated by the kernel. Source names,
Knowledge Unit IDs, Page IDs and Diagram IDs remain because they express
semantic relationships. Session, Target, Attempt and checkpoint IDs do not.

## Consequences

Context compression resumes from living Artifacts rather than an Attempt
history. Parallelism is selected by the host for independent evidence and page
work. The kernel no longer schedules agents, but retains revision binding,
scope and locator validation, exact unit coverage, logical-link binding,
review digest binding, Candidate validation and atomic Publication.
