# Repository Knowledge Layer

The repo-wiki skill builds and incrementally updates a pull-based knowledge
layer that coding agents read before changing a codebase. Vocabulary for
developing the skill; runtime rules live in `skills/repo-wiki/`.

## Language

**Knowledge Layer**:
The OKF bundle in the wiki directory, committed next to the code it describes;
`repo-wiki.yaml` marks its root.
_Avoid_: Domain Wiki, Publication, generation

**Hub**:
A git repository that holds only the Knowledge Layer, with each Source as an
ignored child directory.
_Avoid_: Workspace

**Source**:
A git repository the Knowledge Layer describes: the repository itself, or one
child directory of a Hub.
_Avoid_: registered Source, Files Source

**Module**:
A unit found by `okf scan`: a manifest-declared module or a top-level code
directory, with a code root such as `src/` split per child directory, the
domain packages of a single build split further, and top-level test roots left
out; the grain of coverage.
_Avoid_: Source Area, Domain

**Trigger**:
A place where work enters production code: a route, RPC service, message
listener, scheduled job, event listener, command or startup hook, found by
`okf scan`. Every trigger file sits in a Workflow or Flow Page's Scope or a Not
covered row.
_Avoid_: entry point (a process entry such as `main`), endpoint

**Page**:
One OKF concept document of type Architecture, Glossary, Conventions, Overview,
Module, Workflow or Flow; Schema and Table pages are generated by the database
extension, the Map page (`system-map.md`) by stamp. Its path is derived from
its type, name, Source and Scope.
_Avoid_: page packet, Knowledge Unit

**Role**:
What a Page is for at its place in the wiki; it decides the path, template,
required sections and Canon tables. The Architecture page of a Hub (with the
Contracts table) and of a single repository share a type but not a role.

**Canon**:
The Glossary, Conventions, Architecture and (in a Hub) each Source's Overview
and Conventions pages. The Glossary and Conventions pages are settled before
any other page, the reference for names and rules; the Architecture and
Overview pages are assembled after the pages below them.

**Overview**:
The Canon page of one Hub Source (`sources/<s>/overview.md`): its structure,
dependency direction and Not covered rows.
_Avoid_: source architecture, README

**Flow**:
A Page that traces an end-to-end path across Sources through Contracts, with a
call chain table and a sequence diagram; a flow inside one Source is a
Workflow.
_Avoid_: cross-repo workflow, E2E page

**Contract**:
An interface two Sources of a Hub share, derived by `okf scan` from code and
manifests: a route and its clients, an RPC service and its stubs, a topic, a
table, a library; identified as `<kind> <key>` (`http POST /orders/{}`). A
Flow page or the Architecture page claims it in `contracts` and describes it;
an HTTP client call no Source serves is external.
_Avoid_: link, API edge, dependency (a module import)

**Change order**:
Which side of a Contract changes and ships first, and what compatibility the
other side relies on; a column of the Contracts table.

**System map**:
The generated Map page of a Hub listing every Contract with its sites and the
pages that describe it.
_Avoid_: dependency graph, service map

**Derived file**:
A file the kernel renders from the pages and git, never edited: each
`index.md` (root, and per Source in a Hub), `log.md` and `system-map.md`.
Stamp rewrites them; validate reports one that differs.

**Scope**:
The source globs a Page answers for; with the cited files it forms the
page-to-source mapping behind coverage, impact and staleness.
_Avoid_: Page Scope, owner

**Locator**:
A plain `path#Lx-Ly` relative to the repository or Hub root; the line range is
optional. A path with spaces is bracketed: `<my app/x.py>#Lx-Ly`.
_Avoid_: URI, evidence ID

**Citation**:
An OKF footnote whose definition starts with a Locator.
_Avoid_: Evidence Anchor

**Revision**:
The Source commit a Page is bound to: its writing baseline while draft, the
commit it was checked against once stable.

**Current**:
A Revision whose Source content equals HEAD outside the wiki directory, so
wiki-only commits keep a Page current.

**Stale**:
A Page whose Scope or cited files, or a site of a Contract it claims, changed
after its Revision.

**Todo Block**:
An `<!-- okf:todo -->` comment holding a discovery brief or pending changes; a
Page with one cannot be stamped. Todo Blocks are the only work state.
_Avoid_: progress file, ledger, notes

**Draft** / **Stable**:
OKF `status` of a Page before and after it is stamped.

**Review Round**:
One pass by a fresh reviewer over every Draft. The reviewer reads only the
Pages, the Sources and the previous round's Review Report.
_Avoid_: re-review

**Review Report**:
`_review.json`: one round's verdict and issues, bound to the Drafts by
`subject_digest`; the next round reads it as input. Issues carry no IDs or
status.
_Avoid_: issue ledger

**Stamp**:
The kernel action that turns reviewed Drafts Stable: derives `sources`, writes
`generated`, `verified` and `stamp` (`content_sha256` over the body, the
frontmatter except `status`, `sources`, `verified` and `stamp`, and
`reviewed_by`, the approving reviewer), and renders the Derived files.
_Avoid_: publish

**Change Guide**:
A cited `Change | Start at | Also change | Verify` row: a change the scope
really gets, where it starts, what must change with it and how to check it.
Every Module, Workflow and Flow page has one; cross-module rows live in
Architecture (or a Source's Overview); a Contract's row is in the Contracts
table.
`okf impact --files` hands matching rows to an agent about to edit a file.
_Avoid_: change impact, co-change rule

**Database binding**:
The `repos` of a database in repo-wiki.yaml: the sources whose code uses it.
Many-to-many; a repository usually uses one database, one database may serve
several repositories. Schema rules (`include` / `exclude` globs such as
`t_order*`, `*_log`) decide which tables a capture takes.

**Hint**:
An `<!-- okf:hint ... -->` comment a template puts under a section to say what
it should answer; pending work until the writer answers and deletes it.

**Assembly Test**:
Keep what takes more than one file or a record outside the code to rebuild
(a call chain across files, a set of files that change together, a recorded
reason); leave out what one file answers at a glance.
_Avoid_: Grep Test

## Relationships

- A **Page** covers **Modules** through its **Scope**; every **Module** is in
  some **Scope** or in a Not covered table (Architecture, or its Source's
  Overview in a Hub).
- Every **Contract** is claimed by a **Flow** page or the Architecture page, or
  excluded by a Not covered row matching one of its site files; a change to
  any site of a claimed **Contract** makes the claiming **Page** **Stale**.
- A **Page** is **Stale** when a file in its **Scope** or a cited file changed
  since its **Revision**; `okf update` turns it back into a **Draft** with a
  **Todo Block** listing the changes.
- A **Stamp** needs zero validation errors, no **Todo Block**, clean
  **Sources** and an approved **Review Report** (or `--unreviewed`, refused while
the Review Report requests changes).

## Flagged ambiguities

- "Verified" means two things: a command row whose Status is `verified` (it ran
  successfully during research), and a page's OKF `verified` trust record
  (review approval). Keep them apart in code and docs.
